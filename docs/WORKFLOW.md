# 实录工作流、能力与独立化设计

核查日期：2026-09-30。源码依据：qiuyiwu-site `c98253cd0cc71bfda6da998eb5d20eeab32fa988`。本次读取的是本地 Git 提交中的源码及公开能力清单，没有重新验收生产后台生成或发布。

## 1. 产品定位

实录工坊将“一次真实发生的表达”变为“可阅读、可引用、可长期保存的内容资产”。核心价值是忠实整理：保留原意、第一人称、故事、案例与限定条件，去掉口语噪声，补齐章节和配图，让读者更容易理解现场表达。

适用场景：演讲实录、课程整理、访谈整理、分享会归档。若扩展到多人会议，必须先确定讲者归属与哪些内容可公开；目前不自动识别说话人。

独立产品由三个层面组成：**生产工作台、可迁移的整理引擎、独立阅读产物**。站点是一个发布目的地，讲者身份和模型服务是配置。

## 2. 原有工作流：七步制作规范

来源：`.agents/skills/speech-recap/SKILL.md`；以下是原有规范总结，不代表七步都已经自动化。

| 步骤 | 输入和动作 | 产物 / 质量要求 |
|---|---|---|
| 场次配置 | 标题、日期、场合、受众、取材范围、脱敏要求、色彩、公开范围 | 一场一份配置 |
| 1 解析课件 | PDF 逐页渲染、文字提取、拼图、人工识别主题 | 页码 → 主题 → 章节地图；乱码页看图 |
| 2 解析逐字稿 | 通读真实讲述顺序、价值点、原话、口误、敏感项 | 整理笔记和待处理清单 |
| 3 对齐大纲 | 逐字稿结构与 PPT 页序对齐 | 小标题 + 页码 + 要点 + 关键原话 |
| 4 成文 | 去填充、纠口误、顺逻辑，保留第一人称与真实案例 | 客观正文；不增加观点或虚构细节 |
| 5 配图落地 | 关键课件页、可选现场照、图注、HTML 模板 | 图文页、SEO 元数据、Article JSON-LD |
| 6 脱敏弱化 | 匿名化企业、个人和场次指定内容 | 文本与图片均需检查，避免图片泄漏 |
| 7 验收发布 | 检查链接、图片、排版、人工审核、部署 | 人工认可后上线，并核验线上结果 |

课件图片的 `<deck>-<page>.webp` 命名是来源关系：它把文章段落与课件页联系起来，未来可以统计某页被哪些场次使用。独立模块应将这层关系升级成结构化字段，而不只靠文件名猜测。

## 4. 必须拆掉的耦合与缺口

1. **身份耦合**：提示词、作者、页脚和 JSON-LD 固定讲者与域名。改为项目配置。
2. **存储耦合**：草稿在主站 `admin/recap-drafts`，依赖 `dna_paths`。独立数据目录，不随代码发布。
3. **模型耦合**：原模型地址、密钥查找路径、预算模块绑定站点。提供可替换的模型接口，密钥仅由环境注入。
4. **呈现耦合**：模板依赖主站导航、CSS、JS、原子库。阅读产物应自包含。
5. **发布耦合**：操作 `library-data.js`、索引脚本、Git 与主站部署。拆为“导出成品”和“发布适配器”。
6. **复核缺口**：原后端注释把人工复核交给前端，未校验复核记录及具体正文版本。独立引擎必须在服务端强制检查。
7. **状态缺口**：原 `publish` 把 Git 过程总体 `ok` 作为 `pushed`，即便 `push=False` 也可能误报；索引或推送失败仍可能返回总体成功。独立模块分别记录保存、复核、导出、上传与线上验证。
8. **任务缺口**：原后台任务保存在内存，进程重启丢失。批量 / 长稿阶段需持久队列；v0.1 明确只做同步调用。
9. **来源缺口**：原 AI 直接产 HTML，没有逐节结构化原稿关联。首版补来源 ID，但仍需人工检验引用是否真正支撑内容。

## 5. 独立小应用：功能、信息架构、UI

### 功能边界

首版闭环：逐字稿输入 → 原文分段 / AI 初稿 → 逐节人工修改 → 脱敏疑点提示 → 当前版本复核 → 文章包 / 迁移包导出。

全文不直接公开；读者产物仅含人工正文与必要的场次信息。原稿、模型信息、整理要求、审核人和历史留在私人项目数据中。

### 信息架构

- 实录列表：标题、讲者、当前复核状态。
- 新建实录：场次信息、逐字稿、取材范围、脱敏规则。
- 整理区：初稿生成、逐节正文编辑、来源编号、原稿对照。
- 检查与交付：疑点清单、人工复核、阅读预览、成品导出、迁移备份。

### UI 规范

纸白背景、深绿色动作、清晰的阅读层级；正文占主区域；原稿和配置按需展开。保存与复核状态显式显示。修改后提示未保存；切换稿件保护未保存内容。AI 重生成单独保存，用户主动载入编辑区。

## 6. 技术和数据结构

```text
浏览器工作台 → 本机 HTTP API → Store / 整理引擎
                                  ├─ SQLite 项目存储
                                  ├─ 可替换模型服务（可选）
                                  └─ HTML / Markdown / JSON 导出
```

项目字段：`schema_version`、`id`、`revision`、`config`、`transcript`、`sources`、`engine`、`human`、`history`、`review`、`exports`。

章节字段：`title`、`body`、`source_ids`。引用段落含原始文本，保留原来已有的时间码。复核摘要覆盖配置和人工正文，内容变化后失效。SQLite 事务与 revision 冲突检查避免静默覆盖。

迁移有两个层级：JSON 迁移包恢复最新内容并重新复核；停止进程后复制数据库恢复完整工作区。应用层 `Store` 不依赖 Web 框架，可在其他 Python 产品中调用。

## 7. 后续阶段与验收条件

| 阶段 | 增量 | 完成判据 |
|---|---|---|
| v0.1 文字闭环 | 当前仓库 | 新环境无主站依赖启动；建稿、编辑、复核、导出、迁移往返通过 |
| v0.2 图文闭环 | PDF / PPT 解析、缩略图、页码映射、配图和图注 | 图片与正文均有原始出处；导出包离线无丢图；脱敏覆盖图片 |
| v0.3 长稿与模型 | 持久任务、分段生成、失败续跑、真实模型质量评估、预算控制 | 长课程无截断和静默丢段；失败可恢复；原稿覆盖率可审阅 |
| v0.4 发布与检索 | 静态站 / CMS 适配、发布回执、公开索引 | 部署失败不显示已发布；线上 URL 验证成功；私人原稿不进入索引 |
| 多人版（另立范围） | 登录、角色、租户隔离、审计、协同编辑 | 权限与数据隔离单独验收后才允许公网部署 |

v0.1 是从既有流程提炼后重新实现的通用文字应用，并非原站全量功能的原样复制。公开仓库不携带真实客户素材、课件或生产部署配置。
